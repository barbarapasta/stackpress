# Task 00007 Evidence: The Plain Panel In The Blog

Recorded 2026-10-05 against `templates/blog` built with `yarn blog build` and served in production mode on a spare
port through a temporary config (since removed), with no provider key set, so the agent answered with the blog's
offline model (`plugins/app/agent.ts`). Chromium 1243 drove it through `panel-browser-run.mjs` (in this folder),
which signs in through the real sign-in form (`developer`, from the seed) and clicks, types and taps as a person
would. Nothing was minted or faked: every image is a screenshot of the page the server rendered, with the panel in
the state the person left it in. The script was run three times, each on a freshly pushed and seeded database:

| Scenario | Server | Log |
| --- | --- | --- |
| `main`, wide (1280 x 800) then narrow (390 x 844, two times pixel density, touch) | the blog as shipped | `00007-browser-run-main.txt` |
| `limit` | `agent.limit` set to 20 tokens | `00007-browser-run-limit.txt` |
| `nokey` | `agent.providers` empty | `00007-browser-run-nokey.txt` |

Every line of a log is `ok` or `FAIL`. The final runs print `all checks passed`. The main log also holds the
accessibility tree of the open panel as the browser reports it.

Wide images are 1280 x 800 unless the line says half. "Half" images are the right 640 px of that screen, kept only
to save space. Narrow images are 780 x 1688 (390 x 844 at two times) or 390 x 844 where the page is plain.

## What the runs checked besides what the images show

From `00007-browser-run-main.txt` (each line there is `ok`):

- Server render: the HTML sent before any script has the launcher button (`aria-expanded="false"`) and not the panel.
- Hydration: no console error or page error on load, after opening, or in the whole run. The only failed request not
  on the blog was an article banner image from an outside host the sandbox cannot reach.
- Keyboard: Tab reaches the launcher; Enter opens and puts focus in the message field; focus lands on a waiting card
  (the card, not a button, so a stray key press approves nothing); Tab goes to Approve then Decline; after Decline
  focus is on the card; Escape closes and focus returns to the launcher.
- Screen reader: the live region said "Comment delete was declined."; the accessibility tree shows a labelled
  complementary region, a log called Conversation, a labelled Message field, named buttons, and no unnamed control.
- A removed chip is absent from the request body (`context.items` has two items, not three); the picked model
  (`openai/gpt-6.1-sol`) and the anti-forgery token (64 hex characters) are in it.
- A reply arriving in 90 pieces 45 ms apart (narrow screen): while at the end the view stayed at the end; after scrolling up, more
  arrived, the scroll position did not move, a "Jump to latest" button appeared, and pressing it went to the end.
- Contrast: worst measured text pair 5.56:1 (white on the accent colour), all others above 5.9:1; measured in the
  browser from computed colours, transparency included.
- File attach: not driven, because the blog supplies no upload handler, so there is no attach control (checked).
